<h1 align="center">拾字</h1>

<p align="center"><strong>打过的字，随时找回。</strong></p>

<p align="center"><a href="README.md">English</a> | <strong>简体中文</strong></p>

## 为什么做这个

给 AI 写了一大段想法，结果网络出了问题，怎么也发不出去？

刷新一下，草稿没了，才想起来刚才忘了复制？

想重新写一遍，却已经没力气，也想不起刚才是怎么说的了？

我做拾字就是因为这件事。大意还记得，可刚才想到的背景、细节和措辞都要重新组织。有时候已经写累了，再打一遍，也很难说得像刚才那么清楚。

拾字在后台记下输入过的文字。草稿丢了，就像打开剪贴板历史一样，找出那一段，复制回去。最初是为了留住给 AI 写的想法，平时写消息、填表、搜索时也能用上。

目前提供 Windows 版，支持中英文界面，可以搜索历史、复制整段文字，也可以只复制选中的部分。

## 特色

- **中文输入法适配**：尽量记下选词后真正上屏的“你好”，跳过取消的拼音组合，并对不同通道重复报告的同一次输入去重。
- **保留删改前的旧稿**：输入框里的文字删空后，记录显示“已清空”，删改前的版本仍可查看。也会跟踪退格、Delete 和部分选区编辑。
- **跨 Windows 应用恢复文字**：在后台运行，可以记录网页和其他受支持的 Windows 应用中的输入，无需安装浏览器插件。
- **只记录新输入**：打开已有文档时，原有正文只用来比较后续改动，不会整篇存进历史。

## 安装和使用

从本仓库的 **Releases** 页面下载 `TypeTrail-Setup-1.0.0-x64.exe`。需要 **Windows 10 / 11 x64**，也支持部分 32 位应用中的输入。本次只发布 Windows 版。

运行需要 **.NET Framework 4.8 或更高版本**。如果安装器提示缺少运行环境，请先安装 [Microsoft 官方运行时](https://dotnet.microsoft.com/download/dotnet-framework/net48)，再运行拾字安装包。

1. 安装后，在开始菜单搜索 **拾字** 打开。
2. 让它留在后台，照常打字。右上角的状态按钮会显示录入情况，点击可以暂停或恢复记录。
3. 要找回文字时，按 **Alt + 反引号键（&#96;）** 呼出窗口。这个键通常在 Esc 下方、数字 1 左边；快捷键可以在设置里改。
4. 在左侧选一条记录，也可以按文字或应用名搜索。点击 **复制整段**，或拖选一部分后点击 **复制选中**，再回到原来的应用粘贴。

关闭窗口或按 Esc 会收起到后台，点击托盘图标可以再次打开。要彻底退出，请用托盘菜单。开机自动运行可以在安装时或设置里开启。

主界面的太阳 / 月亮按钮用来切换主题，地球按钮用来选择简体中文、English 或跟随系统。默认保留 **50,000 字符**，满了会自动清理较早的内容。保留字数、退出后是否保存历史，以及不记录哪些应用，都可以在设置里调整。

在输入框里删空文字后，对应记录会显示 **已清空**，保留的旧稿可以在右侧的版本下拉框里查看。清空输入框，不会同时删除拾字里的历史。

**请先运行拾字，再开始输入。** 没有录到的文字，事后无法补回。

安装包目前没有 Windows 发布者签名。请从本仓库的 Releases 下载，并用同一版本中的 `SHA256SUMS.txt` 核对文件。不要为了安装而关闭安全防护。

## 隐私与数据

**程序不会上传输入历史，也不会将你输入的文字发送到服务器。** 不需要注册或登录，也没有云同步或输入上传功能。历史保存在本机 `%LOCALAPPDATA%\TypeTrail`，使用当前 Windows 用户身份加密。同一用户身份下运行的恶意程序仍可能读取数据；已经复制或导出的正文也不受这层加密保护。

标准密码框、只读区域和排除列表中的应用会被跳过，但部分自定义输入框无法可靠识别。**输入密码、验证码、密钥等敏感内容前，请暂停记录，或事先排除相关应用。**

卸载默认保留历史和设置。若想一并删除数据，请先退出程序，再删除上述目录及已有备份。清空历史不等于安全擦除，剪贴板、系统快照等位置的副本需要另行处理。

请在你有权使用的设备和账户上运行拾字，并确保相关使用者知情同意。不要未经允许记录他人的输入。

## 哪些情况可能记不全

拾字通过 Windows 输入事件和控件提供的文字信息记录输入。已测试原生 x64 / x86 编辑框、网页输入框，以及微软拼音、搜狗拼音、英文和中英文混输，但不能保证所有应用和输入法都能正常记录。

受保护或权限更高的程序、部分自绘输入框、只提供原始键码的编辑区，以及某些自定义粘贴操作，可能记不到或只记下一部分。复杂的光标移动、选区和撤销操作，也未必能完整还原。遇到无法可靠跟踪的修改，程序会把片段保留为修改前内容。

系统或应用更新、程序卡顿、存储故障也可能影响记录。如果开启了保留历史，新记录却未能写入磁盘，程序会取消正常退出并给出提示。强制结束进程或断电，仍可能丢失未保存的内容。

看到受限或不完整提示时，请先把重要文字手动复制一份。长稿也记得及时另存，别把拾字当作唯一备份。

### 输入处理

键盘活动、输入法提交和控件文字先经过归属、保护和去重，再进入输入日志。
原有文档内容仅用作临时比较基线，不会为了补齐历史而整篇导入。

中文以确认后的文字为准。取消的拼音和多个通道报告的同一次输入不能重复保存。
光标和选区只在能够确认属于已记录文字的范围内跟踪；不能可靠判断的操作保留
为带标识的旧片段。删空显示清空状态，完整旧稿单独保留。

历史压缩后使用当前 Windows 用户身份加密，并以原子替换方式保存。读取失败时
保护原文件并重试，恢复期间的新输入保留在内存等待合并。新历史未能写盘时，
正常退出会被取消并提示；强制终止和断电的限制见上方“哪些情况可能记不全”。

主程序 C# 文件由 `src/TypeTrail/sources.txt` 显式列出。原生桥及 x86 宿主分别
构建；组件固定文件名和接口保留兼容性，避免干扰其他应用中仍被 Windows 加载
的输入桥。各采集通道覆盖不同控件，不能互相简单替代。

</details>

## 从源码构建

<details>
<summary>工具链和构建命令</summary>

在仓库根目录使用 Windows PowerShell 5.1 运行以下命令。
运行环境为 Windows 10 / 11 x64 和 .NET Framework 4.8 或更高版本。

### 构建工具

- Windows 自带的 .NET Framework C# 编译器。
- Visual Studio 2022 Build Tools，包含 MSVC 14.41.34120 的 x64 和 x86 工具。
- Windows SDK 10.0.22621.0。
- Inno Setup 7.1.0，用于生成安装包。

原生组件的脚本使用上述 MSVC 和 SDK 路径。如果工具安装在其他位置，
请先调整 `src/native/build.ps1` 和 `src/companion/build.ps1`。

### 编译应用

```powershell
powershell.exe -NoProfile -File .\build.ps1
```

命令会将 WPF 主程序、原生 x64 输入桥和 x86 宿主编译到 `bin/`。
完整的受支持输入覆盖需要这三个组件。主程序源文件由
`src/TypeTrail/sources.txt` 列出；编译时会检查缺失、重复和未列入清单的文件。

### 生成安装包

```powershell
powershell.exe -NoProfile -File .\installer\build-installer.ps1 -CompilerPath C:\path\to\ISCC.exe
```

输出为 `dist/TypeTrail-Setup-1.0.0-x64.exe`。如需指定应用编译产物所在目录，
传入 `-PayloadDirectory`；安装包输出目录使用 `-OutputDirectory` 指定。
中间文件位于 `.build/installer/`。

安装包只包含明确列出的运行文件、用户说明和 Unicode 许可。
不要把个人历史或设置放进构建目录。用户数据保存在
`%LOCALAPPDATA%\TypeTrail`，与安装目录分开。安装包目前没有 Windows 发布者签名。

</details>
